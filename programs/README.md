# Fixture instructions

Build host interfaces and all five fixture artifacts together with
`cargo xtask programs`. A fresh stack loads the rebuilt programs; stop an old
stack with `cargo xtask stack down` before testing fixture changes.
Redshift slim and slim-upgraded retain only the top-level probes below.

The tables name a current scenario or indirect producer for every live
instruction. Scenario paths are relative to `<family>/src/scenarios/`.

## Wire compatibility

Live instruction tags, PDA seeds, account layouts and account-meta ordering are
preserved. Redshift uses explicit Borsh discriminants so retired tags remain
invalid. The fixture cleanup intentionally removes four unused payload fields:
`DelegateCpiArgs.valid_until`, `ScheduleCommitCpiArgs.has_magic_vault`,
`ScheduleCounterTask.error`, and Redhat's direct-CPI player vector. Their host
builders and on-chain decoders change together; rebuild and reload the fixtures
when adopting these interfaces.
